## 🎯 **خلاصه عملیات:**

### **چه کاری انجام می‌شود؟**
- ✅ حذف نرم (Soft Delete) خدمات مشترک
- ✅ فقط برای دپارتمان‌های غیر از "اورژانس" و "تزریقات"
- ✅ با Backup کامل
- ✅ با امکان بازگشت (Rollback)
- ✅ با Transaction Management

### **چه چیزی حذف نمی‌شود؟**
- ✅ خدمات مشترک دپارتمان "اورژانس"
- ✅ خدمات مشترک دپارتمان "تزریقات"
- ✅ خدمات اصلی (Services)
- ✅ دپارتمان‌ها (Departments)

### **نوع حذف:**
- ✅ **Soft Delete**: فقط `IsDeleted = 1` و داده‌ها قابل بازیابی
- ❌ **Hard Delete**: نه، داده‌ها حذف فیزیکی نمی‌شوند

### **مرحله 3: اجرای حذف (با احتیاط)** ⚠️

#### **گام 1: بارگذاری اسکریپت**
```bash
# از Command Line
cd C:\Users\Developer\source\repos\ClinicApp\Scripts
sqlcmd -S . -d ClinicDb -E -i "DELETE_SHARED_SERVICES_SAFE.sql"
```

یا در SSMS:
1. باز کردن فایل `DELETE_SHARED_SERVICES_SAFE.sql`

#### **گام 2: اجرای اول (فقط مشاهده)**
- ✅ اسکریپت را اجرا کنید (F5)
- ✅ گزارش را بررسی کنید
- ⏸️ در CHECKPOINT متوقف می‌شود

**پیام:**
```
⏸️  برای ادامه، کامنت CHECKPOINT را حذف کنید و دوباره اجرا کنید.
```

#### **گام 3: تأیید و اجرای نهایی**
1. خط زیر را در اسکریپت پیدا کنید:
```sql
RETURN; -- ⛔ این خط را حذف کنید برای اجرای واقعی
```

2. این خط را **کامنت** کنید:
```sql
-- RETURN; -- ⛔ این خط را حذف کنید برای اجرای واقعی
```

3. **UserId** خود را جایگزین کنید:
```sql
DECLARE @DeletedByUserId NVARCHAR(450) = 'SYSTEM_ADMIN'; -- 🔧 تغییر دهید به UserId واقعی
```

4. اسکریپت را **دوباره اجرا کنید** (F5)

#### **گام 4: بررسی نتیجه**
✅ پیام موفقیت:
```
✅ Transaction با موفقیت COMMIT شد.
✅ عملیات با موفقیت انجام شد!
```

❌ پیام خطا:
```
❌ خطا رخ داد! Transaction ROLLBACK شد.
```

---

### **مرحله 4: بررسی نهایی** ✅

```sql
-- بررسی تعداد خدمات مشترک باقی‌مانده
SELECT 
    d.Name as 'دپارتمان',
    COUNT(ss.SharedServiceId) as 'تعداد'
FROM SharedServices ss
INNER JOIN Departments d ON ss.DepartmentId = d.DepartmentId
WHERE ss.IsDeleted = 0
GROUP BY d.Name
ORDER BY d.Name;
```

**نتیجه مورد انتظار:**
- ✅ فقط دپارتمان‌های "اورژانس" و "تزریقات" خدمات مشترک دارند
- ✅ سایر دپارتمان‌ها خدمات مشترک ندارند

## 🔄 **بازگشت و بازیابی:**

### **حالت 1: بازگشت فوری (قبل از COMMIT)**
اگر Transaction هنوز COMMIT نشده، فقط:
```sql
ROLLBACK TRANSACTION;
```

---

### **حالت 2: بازگشت بعد از COMMIT (با اسکریپت)**

#### **گام 1: اجرای اسکریپت بازگردانی**
```bash
sqlcmd -S . -d ClinicDb -E -i "RESTORE_SHARED_SERVICES.sql"
```

یا در SSMS:
1. باز کردن فایل `RESTORE_SHARED_SERVICES.sql`
2. اجرای اولیه (F5) → متوقف در CHECKPOINT
3. حذف کامنت `RETURN;`
4. اجرای نهایی (F5)

---

### **حالت 3: بازگشت کامل (با Backup)**
```sql
USE master;
GO

-- بستن کانکشن‌ها
ALTER DATABASE [ClinicDb] SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
GO

-- Restore
RESTORE DATABASE [ClinicDb] 
FROM DISK = N'C:\Backup\ClinicDb_Before_SharedServices_Delete.bak'
WITH REPLACE, STATS = 10;
GO

-- بازگرداندن به Multi User
ALTER DATABASE [ClinicDb] SET MULTI_USER;
GO
```

## ❓ **سوالات متداول:**

### **Q1: آیا این عملیات برگشت‌پذیر است؟**
✅ **بله**، کاملاً! به سه روش:
1. Rollback خودکار در صورت خطا
2. اسکریپت `RESTORE_SHARED_SERVICES.sql`
3. Restore از Backup کامل

---

### **Q2: آیا خدمات اصلی (Services) حذف می‌شوند؟**
❌ **خیر**، فقط جدول `SharedServices` تغییر می‌کند.
- ✅ جدول `Services` دست نخورده
- ✅ جدول `Departments` دست نخورده

---

### **Q3: چه دپارتمان‌هایی مستثنی هستند؟**
✅ دپارتمان‌هایی که **نام** آن‌ها شامل این کلمات است:
- `اورژانس`
- `emergency`
- `تزریقات`
- `injection`

---

### **Q4: چقدر طول می‌کشد؟**
⏱️ بستگی به تعداد رکوردها:
- کمتر از 100 رکورد: ~10 ثانیه
- 100-1000 رکورد: ~30 ثانیه
- بیشتر از 1000: ~1 دقیقه

---

### **Q5: آیا سرویس باید down باشد؟**
⚠️ **توصیه می‌شود** اما **الزامی نیست**.
- ✅ بهتر: در ساعات خلوت
- ✅ ایده‌آل: با سرویس down
- ⚠️ قابل قبول: با سرویس up (با احتیاط)

---

### **Q6: اگر خطا رخ داد چه کنم؟**
✅ اسکریپت **خودکار** Rollback می‌کند!
- Transaction به صورت خودکار لغو می‌شود
- هیچ تغییری در دیتابیس اعمال نمی‌شود
- پیام خطا نمایش داده می‌شود
