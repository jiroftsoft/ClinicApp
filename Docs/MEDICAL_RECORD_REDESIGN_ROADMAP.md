# نقشه راه بازطراحی و بهینه‌سازی پرونده پزشکی (EMR)

**هدف:** تبدیل تب «پرونده پزشکی» به یک ماژول حرفه‌ای، غنی و پزشک‌پسند برای نمایش و جستجوی سال‌ها سابقه بیمار (مثلاً ۵+ سال) بدون ساده‌انگاری.

**اصول:**
- داده‌محور و مقیاس‌پذیر (هزاران رکورد نوبت/پذیرش/تاریخچه)
- دسترسی آسان پزشک: جستجو، فیلتر، نمای زمانی
- خوانایی بالا و چیدمان حرفه‌ای (مشابه EMRهای استاندارد)
- گام‌های اتمیک و قابل تست

---

## سناریوی کامل (User Story)

**بیمار:** رضا — سابقه از ۵ سال پیش: نوبت‌ها، پذیرش‌ها، تاریخچه پزشکی (بیماری‌های مزمن، جراحی، دارو)، ارزیابی تریاژ، اسناد ضمیمه.

**پزشک (یا خود بیمار):**
1. با یک نگاه خلاصهٔ وضعیت را ببیند (خلاصهٔ پرونده در بالا).
2. بازهٔ زمانی انتخاب کند (مثلاً ۳ ماه اخیر، امسال، ۵ سال).
3. در متن توضیحات و عنوان‌ها جستجو کند.
4. بر اساس نوع (نوبت / پذیرش / تاریخچه / تریاژ) یا پزشک معالج فیلتر کند.
5. رکوردها را به صورت خط زمانی (جدیدترین بالا یا پایین) ببیند.
6. برای چاپ یا ارجاع، خروجی PDF/Excel بگیرد.

**سیستم:**
- هیچ‌وقت کل ۵ سال را یک‌جا از DB نمی‌کشد؛ همیشه صفحه‌بندی + فیلتر (تاریخ، نوع، جستجو).
- پاسخ اولیه سریع است (مثلاً آخرین ۲۰ رکورد یا خلاصهٔ آماری).
- جستجو و فیلتر سمت سرور انجام شود تا روی حجم زیاد کار کند.

## وضعیت فعلی (خلاصه)

| بخش | API | صفحه‌بندی | جستجو/فیلتر | نمایش |
|-----|-----|-----------|--------------|--------|
| تاریخچه پزشکی | GetMedicalHistories | ❌ همه | ❌ | لیست ساده |
| نوبت‌ها | GetAppointments | ✅ pageNumber/pageSize | ❌ | لیست ساده |
| پذیرش‌ها | GetReceptions | ✅ | ❌ | لیست ساده |
| تریاژ | GetTriageAssessments | ✅ | ❌ | لیست ساده |

- تب داشبورد: محتوا = `_MedicalRecordShell` با ۴ سکشن؛ هر سکشن با AJAX + RenderPartial برای HTML.
- مشکل مقیاس: تاریخچه پزشکی بدون صفحه‌بندی؛ جستجو و فیلتر زمانی وجود ندارد؛ نمای یکپارچهٔ خط زمانی وجود ندارد.

## فاز ۱ — زیرساخت داده و API (Backend)

### ۱.۱ صفحه‌بندی و TotalCount برای تاریخچه پزشکی ✅ انجام شد
- [x] **IMedicalRecordRepository:** متد جدید `GetMedicalHistoriesPagedAsync(patientId, pageNumber, pageSize, fromDate, toDate, searchText)` با خروجی `(List<MedicalHistory>, int TotalCount)`.
- [x] **IPatientMedicalRecordService:** متد جدید `GetMedicalHistoriesPagedAsync` با خروجی `ServiceResult<PagedResult<MedicalHistoryViewModel>>`.
- [x] **پیاده‌سازی:** فیلتر بازهٔ زمانی روی `StartDate ?? CreatedAt`، جستجو در `Title`/`Description`، `OrderByDescending`, `CountAsync`, `Skip`/`Take`.
- [x] **API:** `GetMedicalHistories` پارامترهای اختیاری `pageNumber`, `pageSize`, `fromDate`, `toDate`, `search` می‌پذیرد و Paged برمی‌گرداند.
- [x] **فرانت:** پشتیبانی از پاسخ صفحه‌بندی‌شده (`data.Items`)، نوار «نمایش X–Y از Z» و دکمه «مشاهده بیشتر».

### ۱.۲ فیلتر و جستجو برای نوبت‌ها و پذیرش‌ها
- [ ] **نوبت‌ها:** اضافه کردن پارامترهای اختیاری `fromDate`, `toDate`, `doctorId`, `search` به API و سرویس؛ برگرداندن `TotalCount` در پاسخ (مثلاً داخل یک wrapper مثل `{ items, totalCount }`).
- [ ] **پذیرش‌ها:** همین‌طور برای پذیرش‌ها (تاریخ، پزشک، جستجو در Notes).
- [ ] **تریاژ:** اختیاری `fromDate`, `toDate` و `TotalCount`.

### ۱.۳ endpoint خلاصهٔ پرونده (Overview)
- [ ] **API جدید مثلاً GetMedicalRecordOverview:** یک درخواست برگرداند: تعداد کل تاریخچه، نوبت، پذیرش، تریاژ؛ آخرین تاریخ نوبت/پذیرش؛ شاید آخرین ۳–۵ رکورد برای «پیش‌نمایش» (اختیاری).
- [ ] هدف: نمایش خلاصه در بالای تب بدون بارگذاری کل لیست‌ها.

## نکات پیاده‌سازی

- **سرویس/رپازیتوری:** فیلترها را در لایهٔ سرویس اعمال کنید؛ از رپازیتوری فقط دادهٔ صفحه‌بندی‌شده و Count بگیرید.
- **فرانت:** با حداقل تغییر در ساختار Shell فعلی، نوار فیلتر را بالای سکشن‌ها اضافه کنید و در هر `loadSection` پارامترهای `from`, `to`, `search`, `page` را از state فیلتر بخوانید و به API بفرستید.
- **RenderPartial:** اگر همان مسیر RenderPartial با مدل لیست حفظ شود، مدل را به `PagedResult` یا لیست صفحه‌بندی‌شده تغییر دهید و در ویو فقط همان صفحه را رندر کنید؛ دکمهٔ «مشاهده بیشتر» در خود HTML یا از طریق data-attribute به JS بگوید صفحهٔ بعد را بگیرد.

این سند به‌عنوان نقشهٔ راه و مرجع برای بهینه‌سازی و بازطراحی ماژول پرونده پزشکی استفاده شود و با هر فاز به‌روزرسانی شود.
